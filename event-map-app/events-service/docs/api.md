# API Events Service — ПР2

Основная бизнес-сущность проекта: **Event** (мероприятие). Пользователи находят
события рядом с собой на карте и фильтруют их по категории и дате; организаторы
публикуют события.

Формальный контракт: [`openapi.yaml`](../openapi.yaml).

## 1. Описание сущности Event

| Поле            | Тип        | Обязательное | Ограничения                                             |
|-----------------|------------|--------------|---------------------------------------------------------|
| `id`            | string     | нет (генер.) | UUID, формируется сервером, только для чтения           |
| `title`         | string     | да           | от 2 до 100 символов                                    |
| `description`   | string     | да           | от 1 до 2000 символов                                   |
| `lat`           | number     | да           | широта в диапазоне [-90, 90]                            |
| `lng`           | number     | да           | долгота в диапазоне [-180, 180]                         |
| `starts_at`     | string     | да           | дата/время в формате ISO 8601 (date-time)               |
| `category`      | string     | да           | одно из: `concert`, `lecture`, `exhibition`, `meetup`, `workshop` |
| `organizer_id`  | string     | да           | UUID создателя, непустая строка                         |
| `created_at`    | string     | нет (генер.) | время создания, только для чтения                       |
| `updated_at`    | string     | нет (генер.) | время последнего обновления, только для чтения          |

## 2. URI и операции

Правила REST: существительные во множественном числе, без глаголов в URI,
вложенность не используется.

| Метод  | Путь                 | Назначение                                              |
|--------|----------------------|---------------------------------------------------------|
| GET    | `/`                  | Информация о сервисе и доступных эндпоинтах             |
| GET    | `/health`            | Проверка работоспособности                              |
| GET    | `/events`            | Список событий: пагинация `page`/`limit`, фильтры `category`, `date_from`, `date_to` |
| POST   | `/events`            | Создание события → 201                                 |
| GET    | `/events/{id}`       | Получение одного события → 200 / 404                    |
| PUT    | `/events/{id}`       | Полное обновление → 200 / 400 / 404                     |
| PATCH  | `/events/{id}`       | Частичное обновление → 200 / 400 / 404                  |
| DELETE | `/events/{id}`       | Удаление события → 204 / 404                            |

## 3. Валидация и единый формат ошибок

Все входные данные проверяются **до** обработки бизнес-логикой (`validation.py`).
Некорректный запрос возвращает `400` в едином формате:

```json
{
  "error": "ValidationError",
  "details": [
    {"field": "title", "message": "длина должна быть от 2 до 100 символов"},
    {"field": "category", "message": "допустимые значения: concert, exhibition, ..."}
  ]
}
```

Коды ошибок:

| HTTP | `error`               | Когда                                             |
|------|-----------------------|---------------------------------------------------|
| 400  | `ValidationError`     | поля не прошли проверку (тип, длина, диапазон, перечисление) |
| 400  | `BadRequest`          | некорректный JSON, пустое тело                    |
| 404  | `NotFound`            | событие с таким `id` не существует                |
| 405  | `MethodNotAllowed`    | метод не поддерживается для ресурса               |
| 500  | `InternalServerError` | непредвиденная ошибка сервера                     |

Проверяемые правила:
- отсутствие обязательного поля → `details` с этим полем;
- неверный тип (например, `title: 123`) → 400, а не 500;
- `lat`/`lng` вне диапазона → 400;
- `starts_at` не в формате ISO 8601 → 400;
- неизвестное поле в теле → 400;
- `page < 1` или `limit` вне `1..100` → 400.
